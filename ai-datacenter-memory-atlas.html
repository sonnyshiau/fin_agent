03 / Package Anatomy

HBM：不是把 DRAM 疊高就自然變快

關鍵是 TSV 垂直互連、近距離 2.5D 封裝與每 stack 極寬的平行 I/O。堆疊主要增加容量；多 stack 才增加獨立外部介面。

堆疊層數 ≠ 外部介面倍增

增加 DRAM die 主要提高容量與內部平行性；HBM2E 的完整 stack 對處理器仍呈現 1024-bit 總介面。

Peak bandwidth calculator

寬而相對低速，勝過窄而高速

Bandwidth (GB/s) = data rate × interface width × stacks ÷ 8

819.2 GB/s理論峰值頻寬；實效仍受存取模式、bank conflict、協定開銷、溫度與排程影響。

05 / Four Independent Axes

「快」至少要拆成四個問題

記憶體選型不是單一排名。HBM 可以有極高總頻寬，但單筆 random access latency 並不因此等於 SRAM。

AXIS_A

Bandwidth

每秒能搬多少資料；看 GB/s 或 TB/s。

AXIS_B

Latency

Request 到第一筆資料回來要多久。

AXIS_C

Capacity

總共能容納多少資料；看 MB、GB、TB。

AXIS_D

Persistence

斷電之後資料是否仍然存在。

高頻寬不等於低延遲把 bandwidth 想成車道總流量，把 latency 想成第一輛車抵達時間。HBM 是「很多條短而寬的車道」，不等於每一次存取都像 SRAM。
06 / Recall Test

最後不要背規格，只記住角色

能正確分類一個名詞，通常就能推回它的實體位置、資料生命週期與系統瓶頸。
